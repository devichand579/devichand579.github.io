Part one · what it means to learn

What does it mean to learn something?

I have been curious about this question for a long time, and it keeps opening into others.

  • How can we tell that a learner has learned some information?
  • Can the same information be learned in different ways?
  • What is information in the first place, and is it the same for everyone who looks at it?
  • Is evolution a way of learning?
  • If it is, is evolution itself a program running on some larger machine? Are we learners living inside other learners?

I don’t have final answers. This blog is my attempt to think through these questions using information theory, Solomonoff induction and evolution, to follow how they converge in what we now call deep learning, and to point out the problems I think are most worth solving next.

If you are reading on a wide screen (hoping you are not a LLM), you may have noticed the grid of dots to the leftside of the margin, and perhaps already guessed what it means. The title is the same puzzle. Here it is as a game. Each box below is a row of dots, filled or empty. What comes next?

Read a filled dot as 1 and an empty one as 0, and the boxes say 000, 001, 010. They are counting in binary, so the next box is 011. The same code indexes every question and chapter on this page, which is why the grid of dots works as a table of contents.

What just happened

You saw three boxes and found a rule that fits them, “count up”. You then used the rule to say something about a box you had not seen. That is what this page means by learning: finding a short rule that explains what you have seen, and using it to predict what you have not.

But “count up” was not the only rule that fits. Here are three, all consistent with the same three boxes:

count up 011
count up to 010, then start over 000
count up to 010, then count down 001

Each one predicts a different next box, and the data so far cannot tell them apart. In fact infinitely many rules fit. You did not weigh them all; you went straight for the shortest. Every learner faces this choice, and the preference for short rules is what makes learning from a few examples possible at all.

Solomonoff’s ideal learner

In 1964 Ray Solomonoff turned that instinct into a precise recipe[3]. Write every rule as a computer program. Then:

  1. Keep every rule. Every program that fits the data so far stays in play.
  2. Trust short rules more. Each program’s weight halves with every extra bit of length.
  3. Let the evidence vote. Predict the next box by the weighted vote of the surviving rules. When the box arrives, drop every rule it contradicts.

The recipe comes with a promise. If the sequence is produced by any rule a computer could follow, the learner’s total mistakes over all time are bounded by the length of that rule in bits[4, 5]. Simple worlds are learned almost at once, and no learner does much better in the long run. This is Solomonoff induction.

Why no one can run it

The promise rests on assumptions no real learner can make. Some programs never finish running, and no procedure can tell which ones, so the recipe can never actually be carried out[5]. Evolution, brains and the networks we train are learners that can be built, and each one has to give up something Solomonoff took for granted. He assumed:

a fixed language for writing rules, in which “short” is measured every possible rule already on the table, ready to be weighed that length is the only cost, and running time is free unlimited time to check each rule against the data data that arrives in one fixed order a learner that only watches, and never chooses what to look at

Drop any one of these and a question opens up. Part two builds, one chapter at a time, the tools needed to see why each is hard. Part three states the six questions properly, with what we would build. Part four goes further, and gets strange: if learners are programs running inside other learners, then information, order, cost and even randomness depend on who is looking.

Part two · the machinery

The tools, one at a time

Each chapter adds one idea and uses only the ones before it, and ends with the question the next one answers. The dots beside each title are its number. Know information theory already? Skip to the perfect learner.

Information is a short description

Before we can say what a pattern is, we need a way to measure information. There are two classic answers. The first measures surprise; the second measures the length of a description.

Shannon: information as surprise

Suppose you know how likely each possible outcome is. That assignment of likelihoods is a probability distribution. Shannon proposed that an outcome you gave probability p carries −log₂ p bits of information[6]. A fair coin’s outcome carries 1 bit; an event you thought had a 1-in-1024 chance carries 10. The average over all outcomes is the distribution’s entropy, written H[6].

Shannon’s measure needs a known distribution, and it describes a whole collection of possible outcomes rather than any one of them. It cannot tell you how much information is in one particular string.

Why logarithms appear everywhere

expand

With b bits you can name 2b different things, so picking one out of N takes log₂ N bits. Probabilities of independent events multiply, while amounts of information should add. Up to the choice of base, the logarithm is the only well-behaved function that turns products into sums[6]. The base only sets the unit.

Programs, and the machines that run them

The second answer needs the idea of a program. A Turing machine is Turing’s model of a computer: a device that reads and writes symbols on a tape according to a fixed table of rules[7]. Turing also showed that a single such machine can imitate any other, if it is handed a description of that machine as input[7]. This is a universal Turing machine, which we write U. For it, programs are just data. Every ordinary computer is universal in this sense.

Kolmogorov: information as the shortest description

Fix a universal machine U. The Kolmogorov complexity of a string x is the length, in bits, of the shortest program that makes U print x. Solomonoff, Kolmogorov and Chaitin reached this idea independently in the 1960s[3, 8, 9]. Writing |p| for the length of a program p:

K(x) = min { |p| : U(p) = x }
  • A thousand zeros: about log₂ 1000 ≈ 10 bits, because you only need to say “1000 zeros”[10].
  • The first thousand binary digits of π: also short, because a program that computes π is short[10].
  • A thousand fair coin flips: almost always about a thousand bits. There is nothing to exploit[10].

Two facts shape everything that follows. Invariance: switching to another universal machine changes K by at most a constant, roughly the length of a program that lets one machine imitate the other[3, 8]. So K belongs to the string itself, up to that constant. Uncomputability: no program can compute K[10]. If one could, a short program could search for “the first string whose complexity is above N” and print it, describing a complex string in about log N bits. That contradiction is a version of the Berry paradox[10]. What you can always do is find some program for x, which bounds K(x) from above.

Any compressor gives an upper bound on K: the length of the compressed file plus the size of a fixed decompressor[10]. Rule 30 is a cellular automaton, a row of cells that each update by looking at their two neighbours under a fixed rule[11]. Xorshift is a random-number generator three lines long. Both come from tiny programs, so their K is small, yet a simple compressor finds nothing to exploit. A compressor is an observer with limited cleverness and limited time. That idea returns in chapter 0110.

Some strings have no description much shorter than themselves. Are those exactly the random ones?

Random means nothing shorter exists

Intuitively, a random sequence is one with no pattern. Chapter 0001 gave a way to say “no pattern”: no short description. This chapter tests that intuition, starting with your own eyes.

Which tapes are random?INSTRUMENT · eight processes, one punch
Each tape was punched by a different process: a hole is a 1, a blank is a 0. Some were written by a one-line rule. One looks like coin flips. Tap a tape to see what wrote it.

Programs must mark their own end

Kolmogorov’s definition hides a loophole. If the machine is told for free where a program ends, the program’s length carries extra information. Exploiting that, every infinite sequence, even a run of fair coin flips, has beginnings that look compressible[10]. The fix, found independently by Levin and by Chaitin, is to require programs to be prefix-free: no valid program is the beginning of another[12, 13]. Telephone numbers work this way. The exchange connects you the moment a complete number has been dialled, without an “end” key.

Prefix-free codes obey the Kraft inequality:

Σp 2−|p| ≤ 1

So program lengths behave like probabilities. Feed the machine fair coin flips as its program, and it reads exactly program p with probability 2−|p|[10]. From here on, K means complexity measured with prefix-free programs.

Three definitions that turned out to be one

A statistical test is a procedure that flags sequences with some rare property, such as having far more 1s than 0s. Three proposals for “random” use different intuitions:

  • Typical: a sequence is random if it passes every statistical test that a computer can carry out (Martin-Löf)[14].
  • Incompressible: no beginning of it can be compressed by more than a fixed amount, K(x1..n) ≥ n − c (Levin, Chaitin)[13].
  • Unpredictable: no betting strategy a computer can carry out makes unlimited money on it (Schnorr).

The three describe exactly the same sequences, which is why Martin-Löf randomness is treated as the standard definition. For finite strings there is no sharp line, only degrees: how far K(x) falls below the length of x[10].

The halting problem

Turing proved that no program can decide, for every program, whether it will eventually stop running[7]. This is the halting problem. It is easy to confuse two kinds of stopping. Prefix-freeness tells the machine where a program’s text ends. Nothing can tell it whether running the program ends. That second kind is why K cannot be computed: some short program might still be running, and print x tomorrow[10].

Chaitin’s Ω (omega) is the probability that a program made of fair coin flips eventually halts[13]. Programs that never halt contribute nothing to it. Ω is random in Martin-Löf’s sense, yet its first n bits would settle the halting problem for every program up to n bits long[13, 10]. Chaitin also proved that a formal proof system can certify strings as random only up to a complexity set by its own size, so almost no specific long string can be proved random.

Randomness depends on who is looking

Each definition above has the form “no observer of a certain power can find a pattern”. Change the observer and the answer changes.

  • Observers limited to efficient computation (polynomial time, the standard model of “feasible”): short programs can produce output that looks random to them. This is pseudorandomness, and modern cryptography depends on it[15].
  • Observers that can run any computation: Martin-Löf randomness.
  • Observers that can also solve the halting problem: a stricter notion called 2-randomness. Ω is not random to them, because they can compute it.

We can now say what a pattern is. What would a learner that finds every pattern look like?

The perfect learner (who can’t exist)

The boxes at the top were this same game, made obvious. Here the list is 0s and 1s, arriving one at a time, and before each one you say how likely a 1 is. Assume only that some program, any program, is producing the list.

Solomonoff’s player has three ingredients[3, 5].

  • Every program is a hypothesis: “maybe this program is what is producing the data”.
  • The prior is coin flips. Each program starts with weight 2−|p|, the chance of typing it with fair coin flips from chapter 0010. Every program bit is treated as equally likely to be 0 or 1, and short programs end up favoured simply because they need fewer lucky flips. Occam’s razor, the preference for simpler explanations, comes out of complete ignorance about program bits instead of being assumed[10].
  • Predict by vote, then check. Call a program consistent if its output so far matches the data. Predict the next bit by the weighted vote of the consistent programs. Then observe the true bit and discard every program that got it wrong.

Where K comes in

Several programs can print the same thing. Grouping them changes no prediction, but it shows where Kolmogorov complexity enters. The player never computes K; it only uses 2−|p|. K appears in the analysis: the total prior of everything that prints one output is roughly 2−K, because the shortest program contributes the most. This is Levin’s coding theorem[16, 10].

Why it always works

Write M(x) for the total weight of the programs consistent with data x, and μ (the Greek letter mu) for the true process producing the data. Two facts finish the argument[4, 5].

  • Total surprise is −log₂ M(x). The probabilities you gave at each step multiply together, so their surprises add up to exactly this.
  • The truth is never discarded. The shortest program for μ always prints the right bits, so the surviving weight never falls below 2−K(μ).
total surprise, forever ≤ K(μ) bits

If the truth is itself random, say a biased coin, the same argument bounds your extra surprise beyond the coin’s own, and your probabilities converge to the true ones[4, 5]. For random hypotheses “discard” becomes “multiply by the probability it gave to what happened”. That is Bayes’ rule, with discarding as the special case where that probability is zero.

What “converges” really means

expand
  • It converges in prediction, not identification: hypotheses that agree with the truth on everything seen so far keep their weight[5].
  • It holds along the sequence you actually see, not for histories that never happened[5].
  • It holds with probability 1, which is not the same as “on every random sequence”: Hutter and Muchnik found Martin-Löf random sequences on which it fails[17].
  • You never know when it has converged, because K(μ) cannot be computed[10].

Why this prior and not another

Take any prior w′ that a computer can calculate. Solomonoff’s prior gives every hypothesis at least 2−K(w′) times the weight w′ gives it, because it can always simulate w′ after spending K(w′) bits to describe it[10, 5]. So it is never more than a fixed number of bits worse than any computable prior, and it never gives a computable truth zero weight. That last property is Cromwell’s rule: nothing that could be true should start out impossible.

With a different prior, Bayes still converges, but your mistakes are bounded by −log₂ w′(μ) instead of K(μ)[5]. The prior decides how fast, not where, unless it gives the truth zero weight; then you never arrive. With uncountably many hypotheses even a positive prior can fail, one more reason countably many programs are convenient.

The player keeps updating as bits arrive. What exactly is it keeping track of?

Updating is keeping score

The prior never changes. What changes, as data arrives, is a running score measured in bits.

Each hypothesis starts with a score equal to its description length. Every observed bit adds its surprise, −log₂ of the probability the hypothesis gave to what actually happened (chapter 0001). Weight is 2 to the power of minus the score, so a lower score is better. Writing ν (nu) for a hypothesis and x<t for the bits before step t:

score(ν) = K(ν) + Σt −log₂ ν(xt | x<t)  ·  weight ∝ 2−score

The score is a two-part code length: bits to describe the hypothesis, plus bits to describe the data using it[18, 19]. The current leader is therefore always the hypothesis that minimum description length (MDL) would choose. Solomonoff’s player does not pick it, though; it keeps averaging. In the language of online learning, this update is the exponential-weights algorithm run on log-loss.

Always the true bits, never your own guesses

Learning only happens because the world supplies the next bit. If you appended your own prediction instead, no evidence would come in; you would just grow more confident in what you already believed. That is generating, not learning.

Neural networks show the same split. A neural network is a large adjustable function whose numerical settings, called weights, are tuned to reduce prediction error. When a language model is trained, every position predicts the next word piece (a token) from the true previous tokens, a method called teacher forcing[20]. When it later writes text, it is fed its own outputs, and the mismatch between the two regimes is called exposure bias. Training also differs from Bayes in one important way: Bayes reweights a fixed set of hypotheses, while training a network moves a single hypothesis, its weights, step by step[21].

A score in bits is a code length. Is predicting just compressing, then?

Compression is prediction

Picture Alice sending data to Bob. She does not send a model. Both start with the same learning procedure, and she encodes each point using the model trained on the points before it.

This is the prequential code[22]. Its length is the total surprise on points the model has not yet seen, so memorising the data earns nothing. Where does the cost of describing the model go? Into the early mistakes, made while the model is still learning[19].

The same penalty appears in the Bayesian information criterion, BIC. Two-part coding pays for the model up front; prequential coding pays in instalments.

A family of universal codes

expand

Refined MDL asks for one code for a whole hypothesis class that is never much worse than the best member chosen in hindsight[19]. Normalised maximum likelihood (NML) achieves this optimally. Its penalty measures how many different datasets the class can fit well, which depends on more than the number of parameters: it grows like (k/2) log n for k parameters plus a term that reflects the shape of the class. A Bayesian mixture, a prequential code and a carefully built two-part code all match NML for large n, and a prequential code that uses Bayesian predictions is exactly the Bayesian marginal likelihood[19].

Deep learning is quietly prequential

When a network is trained in a single pass over its data, each batch is scored before the network learns from it. The summed training loss is then a prequential code for the dataset, and Bob could rerun the same training, so the weights never need to be sent[23]. Measured this way, deep networks are strong compressors, and large language models compress even images and audio well[23, 24]. In our reading, a second pass over the same data breaks the code, because by then the model has already seen what it is predicting.

Epiplexity: the area, for a learner with a budget

Finzi and colleagues fix a compute budget T, a limit on how much computation the learner may spend, and take the model P* that gives the shortest total description of the data while running within that budget[25]. They split the total into two parts:

ST = |P*| (structure, “epiplexity”)  ·  HT = expected −log P*(X) (time-bounded entropy)

Their quick estimate of ST is the area under a training curve above its final level, the same area as in the chart above[25]. A pseudorandom tape from chapter 0010 gives a flat curve and no area: to a learner with a budget it is pure entropy, even though a tiny program wrote it[25].

Why trust compression?

  • It rarely happens by luck. The probability that any code beats the true source by k bits is at most 2−k[19]. Compression is evidence of real structure.
  • Short descriptions generalise, by counting. If a hypothesis that takes L bits to describe fits m examples, then with probability 1 − δ its true error is at most (L ln 2 + ln 1/δ)/m[26]. There are only 2L such hypotheses, so a good fit is unlikely to be a coincidence. No assumption that the world is simple is needed.
  • The caveats. The description language is a choice. When no hypothesis in the class is close to the truth, Bayes and MDL can behave badly. And total code length is not the same as useful structure: most of a photograph’s bits are noise.

Everything so far quietly ignored one cost. What happens when time is not free?

Time sends the bill

Solomonoff weights a program by its length only. A program that needs 10100 steps per bit counts the same as one that answers instantly[5].

Levin also charged for time[27, 10]. Writing t(p) for the number of steps program p runs:

Kt(x) = minp [ |p| + log₂ t(p) ]

One extra bit of program costs the same as doubling the running time. Levin search turns this into a procedure for any problem whose answers can be checked: run all programs in parallel, giving each a share 2−|p| of the total computing time[27]. If some program p* solves the problem in time t(p*), Levin search finds a solution in about 2|p*|·t(p*) steps, optimal up to a constant factor that can be astronomically large[27, 10]. Unlike K, Kt can be computed[10]. Schmidhuber’s speed prior weights programs roughly by 2−|p| divided by their running time[28]. Bennett’s logical depth is the running time of a near-shortest program: random strings and trivial strings are shallow, while objects that unfold slowly from short rules are deep[29].

Once time is counted, information depends on the observer. The same tape can be structure to one learner and noise to another[25].

Give the observer more computeINSTRUMENT · rule 30, one column at a time

The magenta column is the Rule 30 tape from chapter 0010, with time running downward. Its bits pass standard statistical tests for randomness[11], so an observer who only sees that column must treat it as noise. Widen what the observer can compute, and the column turns out to be the edge of a structure that was there all along.

If time is not free, how should a learner look for good programs at all?

Finding explanations is the hard part

A learned model that proposes programs is itself a kind of machine. Whose program is it?

Programs that become machines

“Machine” and “program” are roles, not kinds of thing. A Python interpreter is a program to the processor running it and a machine to the Python code it runs.

Every learning system in this page is a stack of loops. In each loop a machine runs, a program is found, and that program becomes the machine for the loop inside it. The pairings below are our reading; the cited works describe the individual loops.

In silicon, training searches for a program, the weights, and the program it finds then acts as a machine. After pretraining you stop changing the weights and give the model prompts, which it treats as evidence about what is generating the text[34]. Networks trained on universal-machine outputs make this explicit. It is a bounded stand-in for a universal machine: a fixed amount of computation per token and a finite input window, with step-by-step reasoning adding running time and, in principle, much more expressive power.

The genomic bottleneck

The human genome holds well under a gigabyte of information, while the brain has around 1014 synapses[35]. Evolution cannot specify that wiring directly, so it has to encode a learner: compact priors and learning rules that grow into a capable brain[35]. Evolution compresses learners rather than solutions.

That completes the machinery. Now the questions can be asked properly.

Built in

Four threads to pull

Is the world one short program? The idea that the universe is computed goes back at least to Zuse. Even if the laws are short, your data stream also has to say where you are in that universe, and that can cost many bits. Short also does not mean shallow: a short rule run for billions of years can have enormous logical depth[29], which an observer with a budget can only experience as complexity.

Are bits a bias? Not as a unit. With k symbols the prior becomes k−|p|, and the invariance theorem absorbs the change[10]. But discrete descriptions do real work. Networks with exact real-valued weights can compute beyond Turing machines, because one real number can hide unlimited information; add noise and that power disappears. Discreteness keeps information finite. The substantial biases are elsewhere: assuming computability, choosing the reference machine, measuring simplicity by length, and fixing the order.

Which order? Data arrives in time order, but its dependencies need not follow it: a proof or a planned sentence is shaped by global constraints. Relativity gives no observer-independent order to events that cannot influence each other, so the underlying structure is a partial order. The direction of time we experience is usually traced to a low-entropy past. What we want is prediction over partial orders, with the learner choosing the order that is cheapest to learn from.

Which machine? Some valid universal machine prints a whole encyclopedia from the empty program, and with such machines the usual optimality results mean little[36]. Müller looked for a machine singled out by machines simulating one another and found that none is. Pretraining is already answering the empirical version, implicitly. What we want is a theory of learned reference machines, so that choosing the training data is choosing the machine.

Part four · where the thoughts get strange

A relativity
of learning

Everything above quietly assumed one learner, standing outside one world, reading it in one order. Drop that assumption and almost every quantity in this blog starts to depend on who is looking. What follows are my conjectures, not results. Each one is where I think one of the six questions leads, and each carries the same code as its question.

CONJECTURE

There are no machines and no programs, only roles.

Every learner is a program to the loop outside it and a machine to the loop inside it. A machine does not optimise itself; the loop around it does. What a machine inside a world has to do, to act well, is carry a compressed model of that world. Cybernetics proved a version of this half a century ago: every good regulator of a system must be a model of that system[37]. So compression is not one strategy among many. It is what acting requires.

Open · If my reference machine is the program my outer loop found, is “which machine?” really the question “which loop am I in?”

CONJECTURE

Explanations must be grown, never looked up, because the data never stops.

Solomonoff’s learner is continual by construction: each update needs only its current weights, never the old data[5]. Pretraining is a frozen snapshot of an amortised version of it[38], and learning from a prompt is an update that vanishes when the prompt ends[34]. That is why I don’t think pretraining has solved learning. The world keeps producing data no snapshot has seen. A bounded learner has to keep compressing its own beliefs as it goes, without forgetting what still matters, and neural networks are notoriously bad at that[39, 40]. How it is done matters less than how it is scored: total surprise on data not yet seen, the prequential score of chapter 0101[22].

Open · What is the right thing to carry forward when you cannot keep the past?

CONJECTURE

Simplicity should be priced in physics, not in a language.

Program length is measured on some machine, and every machine is the program of another; inside computation the regress has no floor. Physics might give it one. Erasing a bit costs a minimum amount of energy[41], so memory is energy spent over time, and computation can trade energy against time[42]. Prediction itself carries a thermodynamic cost[43], and evolution already charges in this currency: a human brain runs on about 20 watts[44]. My guess is one currency: energy over a lifetime.

Open · Neurons and silicon pay different prices for the same computation, so even the physical price depends on the observer.

CONJECTURE

A learner is bounded by the world’s clock, not by its hardware.

A prediction that arrives after the event is worthless, and if the event is a predator, the learner is dead. So the budget is set by how fast the predicted process runs. The same brain is effectively unbounded when predicting geology and badly bounded when predicting a falling cup. Economics calls this bounded rationality[45]; AI has studied answers that improve the longer they run[46] and how to decide how long to think[47].

Open · A promise like Solomonoff’s, stated per deadline instead of “in the long run”.

CONJECTURE

Every observer’s data is a sequence. The world’s is not.

Along your own clock, your experiences arrive in order; that much is guaranteed. How they are produced is different. Events that cannot influence each other have no order that all observers agree on[48], and some quantum processes seem to have no definite causal order at all[49]. Yet from the inside you can never rule out a hidden sequential program underneath, because a sequential machine can simulate any parallel one[7]. So the honest claim is weaker but stranger: no order is preferred, and each observer linearises the world its own way. The universe at the top of the page shows what that does to learning.

Open · Learning over partial orders, where the learner chooses its own linearisation.

CONJECTURE

Choosing your data is choosing what you will become.

Out of everything the world offers, a learner has to pick what to learn from, and that choice shapes every later prediction. One principle: attend wherever your compression is improving fastest, ignoring both what you have mastered and what is pure noise[50]. Epiplexity counts exactly that learnable structure for an observer with a budget[25]. Living things go further and reshape the world they will later observe[51].

Open · Data selection as the learner’s own outermost loop.

Go back to the universe at the top and try each world. Try Rule 30, the rule famous for looking random[11]: to the row reader and the cell dweller it is close to noise, yet the light-ray rider finds structure. Try Rule 110, which can run any program[52]: the cell dweller sees far more pattern than the row reader. Raise k and the numbers move again. Same universe, same learner. What counts as random depended on the order and the memory of whoever was reading.

So what does not change?

If information, order, cost and randomness all depend on the observer, is anything left? Relativity in physics did not end in “anything goes”. Its achievement was finding the quantities every observer agrees on[48]. Learning has a few weak candidates already. Kolmogorov complexity is the same on every universal machine, up to a constant[10]. And epiplexity suggests asking how the structure an observer can extract grows with its budget[25]; I suspect that growth, not any single value, is closer to invariant. I would like a theory of learning built the way relativity was: list what changes from one observer to the next, then build on what does not.

Data, order, cost and randomness change from frame to frame. A theory of learning, like a theory of motion, should be built from what does not.
