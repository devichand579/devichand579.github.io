# How Changes Flow from Main to GH-Pages

## The Complete Flow Explained

```
┌─────────────────────────────────────────────────────────┐
│                    YOU EDIT: MAIN                        │
│  - You write/edit files                                  │
│  - Commit changes                                       │
│  - Push to GitHub                                       │
└─────────────────────────────────────────────────────────┘
                          ⬇️
┌─────────────────────────────────────────────────────────┐
│              GITHUB ACTIONS TRIGGERS                     │
│  (Automated by .github/workflows/deploy.yml)            │
│                                                          │
│  This happens AUTOMATICALLY when you push to main!     │
└─────────────────────────────────────────────────────────┘
                          ⬇️
┌─────────────────────────────────────────────────────────┐
│            GITHUB ACTIONS BUILDS THE SITE               │
│                                                          │
│  Steps:                                                  │
│  1. Checkout main branch code                           │
│  2. Install Ruby, Bundler, dependencies                │
│  3. Run: bundle exec jekyll build                       │
│     → Jekyll generates HTML from your source             │
│     → Output goes to _site/ folder                      │
│  4. Run: purgecss (optimize CSS)                        │
│  5. Copy CNAME file                                     │
└─────────────────────────────────────────────────────────┘
                          ⬇️
┌─────────────────────────────────────────────────────────┐
│          DEPLOY TO GH-PAGES BRANCH                      │
│                                                          │
│  GitHub Actions:                                        │
│  1. Checkout gh-pages branch                            │
│  2. DELETE everything in gh-pages                       │
│  3. COPY _site/* contents to gh-pages                  │
│  4. Commit and push to gh-pages                        │
│  5. Creates message: "Deploying to gh-pages..."        │
└─────────────────────────────────────────────────────────┘
                          ⬇️
┌─────────────────────────────────────────────────────────┐
│           GITHUB PAGES SERVES THE SITE                  │
│                                                          │
│  GitHub automatically:                                   │
│  1. Reads gh-pages branch                               │
│  2. Finds CNAME file                                    │
│  3. Serves site at devichand.com                        │
│  4. Site is LIVE! 🎉                                    │
└─────────────────────────────────────────────────────────┘
```

## Key Points

### 🔧 Main Branch (Where YOU Work)
- Contains your **source code**
- Jekyll files (.md, .yml, .liquid, etc.)
- All your edits go here
- Not directly served

### 🌐 GH-Pages Branch (What Users See)
- Contains **built HTML files**
- Generated automatically by GitHub Actions
- This is what visitors actually see
- You **never edit this directly!**

## Why This Separation?

### Main Branch:
```
_config.yml          ← You edit this
_pages/about.md      ← You edit this
_posts/blog-post.md  ← You edit this
assets/css/style.css ← You edit this
```

### GH-Pages Branch:
```
index.html           ← Generated by Jekyll (HTML)
about.html           ← Generated by Jekyll (HTML)
assets/css/style.css ← Copied from main
```

You don't write HTML - Jekyll generates it from your Markdown/YAML!

## The Automation (GitHub Actions)

Every time you push to main:

```yaml
# This file: .github/workflows/deploy.yml

Trigger: Push to main branch
↓
Build: bundle exec jekyll build
↓
Output: _site/ folder with HTML files
↓
Deploy: Copy _site/* to gh-pages branch
↓
Done: Site is updated!
```

## What Happens Behind the Scenes

### When You Push to Main:

1. **GitHub detects the push** to main branch
2. **GitHub Actions starts** (deploy.yml workflow)
3. **Actions checks out main branch** code
4. **Jekyll runs** on your source files:
   - Reads Markdown → Converts to HTML
   - Reads YAML config → Applies settings
   - Processes includes → Builds pages
   - Runs plugins → Applies enhancements
5. **Output generated**: All HTML files in _site/
6. **Actions checks out gh-pages branch**
7. **Deletes everything** in gh-pages
8. **Copies _site/ contents** to gh-pages root
9. **Commits and pushes** gh-pages branch
10. **GitHub Pages serves** the new content

## Why You Don't Edit GH-Pages

If you manually edit gh-pages:

```
┌─────────────────────────────────────────┐
│  YOU: Edit gh-pages manually           │
│      - Make changes...                 │
│      - Commit...                       │
└─────────────────────────────────────────┘
          ⬇️
┌─────────────────────────────────────────┐
│  Next Push to Main:                    │
│  - GitHub Actions runs                 │
│  - Overwrites gh-pages                 │
│  - Your manual changes: GONE! ❌      │
└─────────────────────────────────────────┘
```

**Lesson:** Always edit main, never gh-pages!

## The CNAME File Exception

CNAME file is special:

```
Main → Jekyll processes → GH-Pages gets CNAME
```

The deploy script (bin/deploy) explicitly preserves CNAME:
```bash
# Keeps CNAME in gh-pages
find . -maxdepth 1 ! -name 'CNAME' ... -exec rm -rf {} \;
```

So:
1. You create CNAME in main
2. Jekyll keeps it in _site/
3. Deploy copies it to gh-pages
4. GitHub Pages reads it
5. Site serves at your custom domain!

## Summary

- **Main**: Source code, templates, config
- **GitHub Actions**: Builder (automated)
- **GH-Pages**: Output (HTML files)
- **GitHub Pages**: Web server

**You Edit:** Main branch only
**Users See:** GH-Pages branch (automatically generated)
**Update Process:** Automatic on every push!
